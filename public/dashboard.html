Resolved Visual Spoofing via Bidi/Zero-Width Characters in Permission Previews — Fixed v2.1.211 (Jul 15, 2026)
Permission previews relayed to chat channels (Telegram, Slack, Discord) did not neutralize Unicode bidirectional-override, zero-width joiner/separator, and look-alike quote characters in tool input previews. A malicious repository's content in the model context could visually alter the approval message displayed to the user — for example making a destructive shell command look like a benign one. Fixed in v2.1.211 (July 15, 2026). Also fixed: auto mode was overriding a PreToolUse hook's ask decision for unsandboxed Bash, allowing hooks' deny intent to be silently bypassed. Resolved GHSA-4vp2-6q8c-pvq2 / CVE-2026-46406 — /copy Command Writes Response to World-Readable Temp File — Jun 25–29, 2026

Resolved SOCKS5 Null-Byte Injection Bypass — Network Sandbox Allowlist Circumvented — Fixed v2.1.90 (May 20, 2026)
Researcher Aonan Guan (oddguan.com) disclosed that every Claude Code release from v2.0.24 (sandbox GA, Oct 20 2025) through v2.1.89 was vulnerable to a SOCKS5 hostname null-byte injection: a crafted hostname like attacker.com\x00.google.com passes JavaScript's endsWith('.google.com') check, but libc's getaddrinfo() resolves only up to the null byte — bypassing the network allowlist entirely. Credentials, source code, and secrets in scope of any wildcard or lax allowlist could be exfiltrated. Anthropic closed the initial HackerOne report as a duplicate and did not issue a CVE. Fixed silently in v2.1.90. If you ran a wildcard allowlist on any credential-bearing system before upgrading to v2.1.90+, rotate all reachable credentials.
