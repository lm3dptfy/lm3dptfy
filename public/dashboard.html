Advisory Claude Code GitHub Action — Supply Chain Attack via Prompt Injection (Fixed claude-code-action v1.0.94) — Jun 4, 2026
RyotaK of GMO Flatt Security disclosed that the official claude-code-action GitHub Action incorrectly trusted any actor whose name ended in [bot], allowing any registered GitHub App to trigger workflows. Attackers crafted issues containing indirect prompt injection payloads that caused Claude to extract GitHub Actions OIDC credentials and exchange them for write-access tokens — enabling arbitrary code injection into any public repository running the action. A secondary vector: the official example issue-triage workflow shipped with allowed_non_write_users: "*", allowing anyone to trigger it, and Claude posted task summaries to the publicly visible workflow summary panel, creating an exfiltration channel. Anthropic rated the issues CVSS 7.8 and paid a bug bounty. Fixed in claude-code-action@v1.0.94 — update your GitHub Actions workflows immediately. The Hacker News · CyberSecurityNews

Resolved v2.1.149 Security Fixes — PowerShell Bypass, Sandbox Write Allowlist & macOS vnode Exhaustion — May 22, 2026
Claude Code v2.1.149 (May 22) shipped four security fixes: (1) PowerShell permission bypass using built-in cd functions — allowed bypassing write restrictions via PowerShell's built-in cd alias; (2) Sandbox write allowlist not applied in git worktrees — files in linked worktrees were not subject to configured path restrictions; (3) PowerShell prefix/wildcard allow rules not pre-approving native executables — caused incomplete enforcement of allow rules; (4) find command exhausting macOS system file/vnode table — could deny service on macOS. Resolved SOCKS5 Null-Byte Injection Bypass — Network Sandbox Allowlist Circumvented — Fixed v2.1.90 (May 20, 2026)
Researcher Aonan Guan (oddguan.com) disclosed that every Claude Code release from v2.0.24 (sandbox GA, Oct 20 2025) through v2.1.89 was vulnerable to a SOCKS5 hostname null-byte injection: a crafted hostname like attacker.com\x00.google.com passes JavaScript's endsWith('.google.com') check, but libc's getaddrinfo() resolves only up to the null byte — bypassing the network allowlist entirely. Credentials, source code, and secrets in scope of any wildcard or lax allowlist could be exfiltrated. Anthropic closed the initial HackerOne report as a duplicate and did not issue a CVE. Fixed silently in v2.1.90. If you ran a wildcard allowlist on any credential-bearing system before upgrading to v2.1.90+, rotate all reachable credentials. Aonan Guan (oddguan.com) · The Register · CyberPress
